# Агентская петля

Обычный запрос к модели — один вопрос и один ответ. В агентской петле модель может сначала
попросить данные: дерево метаданных, структуру объекта, результат запроса к базе. ИИкона
выполняет запрошенное, возвращает результат модели, и так по кругу, пока модель не даст
итоговый ответ или не сработает ограничитель.

Так модель ставит диагноз ошибке по настоящей структуре регистра и рисует диаграмму с
настоящими именами реквизитов, а не угадывает их по тексту.

## Где работает

| Где | Что делает модель |
|---|---|
| «Глубокий анализ» ошибки — на дашборде ошибок, в журнале и статистике мониторинга | смотрит структуру объектов из текста ошибки и, если разрешено, данные; пишет диагноз в журнал |
| [Генератор диаграмм](../диаграммы/README.md), режим «по описанию», и программный `СгенерироватьДиаграмму` | запрашивает структуру объектов и строит диаграмму по ней |

Форма генератора идет через петлю с версии 1.6.1; в 1.6.0 и раньше петля работала только
в программном `СгенерироватьДиаграмму`. Если в описании прямо названы объекты
конфигурации (`Справочник.КИИ_МоделиИИ`), генератор еще до петли кладет их состав в промпт,
и модели не нужно тратить на них раунды.

## Что нужно от модели

В карточке модели на вкладке «Генерация» должен стоять флажок «Поддерживает инструменты
(function-calling)». У 14 из 30 предустановленных моделей он уже стоит. Без флажка:

- «Глубокий анализ» отказывается с подсказкой включить флажок или выбрать другую модель;
- генерация диаграммы идет обычным запросом без инструментов.

Флажок ничего не проверяет: он говорит ИИконе, что модель умеет вызывать функции. Если
поставить его модели, которая не умеет, провайдер вернет ошибку на первом же раунде.

Петля работает во всех форматах API: OpenAI, Anthropic, Google, YandexGPT, GigaChat. Для
GigaChat вызовы переводятся в его формат `functions`.

## Инструменты

Модели доступны четыре инструмента [MCP-сервера](../mcp-сервер/README.md):

| Инструмент | Что возвращает |
|---|---|
| `get_metadata_tree` | дерево объектов конфигурации |
| `get_object_structure` | реквизиты, табличные части и типы объекта |
| `get_configuration_info` | имя, версия и поставщик конфигурации, версия платформы, режим совместимости, список расширений |
| `execute_query` | результат запроса на языке 1С, только чтение |

Список закрыт: новые инструменты MCP-сервера в петлю сами не попадают.

**Запросы к данным в глубоком анализе выключены по умолчанию.** Модель видит только
метаданные, `execute_query` ей не предлагается. Включает их флажок «Разрешить запросы к
данным в глубоком анализе» в обработке «Настройки мониторинга ошибок» раздела «Коннектор ИИ»
(с 1.6.1; раньше — только правкой константы `КИИ_МониторингОшибокНастройки`). В генераторе
диаграмм запросы к данным доступны модели всегда.

Запрос выполняется с правами пользователя, который запустил анализ: ограничения доступа к
данным и права конфигурации работают как обычно, привилегированного режима нет. Запрос со
словами `УНИЧТОЖИТЬ`, `УДАЛИТЬ`, `ИЗМЕНИТЬ`, `ВСТАВИТЬ` (и английскими аналогами)
отклоняется, число строк ограничено — не больше 1000.

## Ограничители

| Ограничение | Значение | Что происходит |
|---|---|---|
| Раундов диалога | 5 | петля останавливается |
| Вызовов инструментов за анализ | 10 | лишние вызовы получают ответ «Лимит вызовов инструментов исчерпан» |
| Результат одного инструмента | 2000 символов | обрезается |
| Весь диалог | 24000 символов | петля останавливается |

Когда петля остановилась по ограничителю, ИИкона делает еще один запрос уже без
инструментов: модель должна сделать вывод из того, что успела собрать. Если и он не удался,
ответ — «Анализ прерван по лимиту; вывод не получен.»

Повторный вызов того же инструмента с теми же аргументами не выполняется заново и не
расходует лимит: модель получает прежний результат.

Ошибка инструмента, например неверный запрос, не прерывает петлю: текст ошибки уходит
модели, и та может исправить вызов в следующем раунде.

## Что остается в базе

- **Журнал запросов ИИ** — каждый раунд отдельной записью: токены, время, стоимость. Раунды
  одного анализа связаны полем «Корреляция агента». Ответы петли не берутся из кеша.
- **Журнал регистрации**, событие `КИИ.АгентАнализа.Вызов` — каждый вызов инструмента:
  идентификатор анализа, имя инструмента, успех, пометки «(из кеша петли)» и «отклонен:
  лимит». Ошибки инструментов пишутся предупреждением в `КИИ.АгентАнализа`: по умолчанию
  мониторинг собирает только уровень «Ошибка» и их не видит. Если в настройках мониторинга
  включен сбор предупреждений, эти записи попадут в журнал ошибок наравне с другими.
- **Журнал мониторинга** — результат глубокого анализа: секция «[Глубокий анализ дата]» с
  числом раундов и вызовов в поле «Описание от ИИ». Повторный глубокий анализ заменяет
  прежнюю секцию, результат автоанализа остается ниже.

## Персональные данные

Все раунды одного анализа идут через
[контроль персональных данных](../контроль-персональных-данных/README.md) с общим набором
подстановок: одно и то же ФИО во всех раундах заменено одинаково. Результаты инструментов,
в том числе строки из `execute_query`, тоже уходят модели подстановками.

Диагноз в журнале мониторинга остается с подстановками. В коде диаграммы подстановки
возвращаются к исходным значениям: этот код читает и правит человек.
