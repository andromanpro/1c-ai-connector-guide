# Последовательная проверка интерфейса ИИконы 1.9.2

1. Обновите расширение в центральной ИИконе и во всех подключенных тестовых базах, затем заново войдите в них. Проверьте, что везде активна версия 1.9.2. После обновления один раз соберите диагностику из центральной базы и УТ, это будет исходный снимок настроек для проверки.

2. Откройте "Чат с экспертом" в своем обычном размере окна. Проверьте, что доступны вопрос, история и кнопки. Наведите мышь на картинки кнопок, должны появляться подсказки. Enter добавляет строку в вопрос, Ctrl+Enter отправляет его.

3. Создайте беседу "Тест А", выберите эксперта и модель. Напишите вопрос в две строки, пока не отправляйте. Перейдите из поля вопроса в другое поле. Создайте через "Новый диалог" беседу "Тест Б", выберите другого эксперта и другую настроенную модель, напишите другой черновик. Переключитесь между штатными вкладками 1С. В каждой должны остаться свои вопрос, эксперт и модель.

4. Закройте вкладку "Тест А" обычным крестиком. Через "Мои диалоги" откройте ее снова. Проверьте восстановление черновика и настроек, затем поменяйте название беседы. Название вкладки должно отображаться в одну строку.

5. В "Тест А" прикрепите через скрепку небольшой TXT с уникальной строкой, например ТЕСТ_БЕСЕДЫ_А. Откройте "Материалы", проверьте имя файла, просмотр и сохранение. В "Тест Б" этот файл сам появиться не должен. Для явного переноса попробуйте "Из другого диалога" и выберите материал из "Тест А".

6. Заполните вопрос и откройте "Перед отправкой", нажмите "Обновить просмотр". Проверьте модель, вопрос, историю, материалы и базы для инструментов. Вернитесь к вопросу, измените его и обновите просмотр еще раз. Здесь показывается состав подготовленного запроса, править текст нужно в исходных полях. Отдельно попробуйте включить и выключить передачу материала, различие должно быть видно в просмотре. Если у эксперта есть категории знаний, проверьте "Подобрать знания" с этим экспертом.

7. Отправьте короткий вопрос из "Тест А" и, пока он выполняется, перейдите в "Тест Б". После завершения ответ должен сохраниться в "Тест А". Затем отправьте другой вопрос из "Тест Б". Проверьте, что ответы и история двух бесед не смешались. На странице "Журнал диалога" должны быть обращения именно выбранной беседы, с ее моделью и состоянием.

8. После завершения запросов закройте всю программу с открытой вкладкой чата. Ошибка "Серверные вызовы при завершении работы запрещены" появляться не должна. Войдите заново и через "Мои диалоги" проверьте историю и сохраненные черновики.

9. Для удаления создайте две отдельные ненужные беседы без связанных материалов. В "Моих диалогах" выделите обе, нажмите удаление и сначала ответьте "Нет". Обе записи должны остаться. Повторите и подтвердите удаление. Должно быть одно подтверждение с количеством, обе записи должны исчезнуть из списка, их открытые вкладки должны закрыться.

10. Основные шаги с двумя беседами, вложением и выходом повторите под обычным пользователем с правом работы с ИИконой. После этого проверьте в веб-клиенте и на серверной базе при её наличии. В ответе отметьте, где именно выполнялся каждый вариант.

Для диагностики используется внешняя обработка ИИконы 1.0.1. Для исходного снимка и при сбое откройте EPF через "Файл - Открыть" в той базе, где проводится проверка. Укажите небольшой период вокруг времени ошибки. По умолчанию стоит последний день, его лучше сузить. Это время самого обращения к ИИконе. Если есть код обращения, вставьте его целиком. Нажмите "Собрать диагностику", затем "Сохранить JSON для поддержки".

При ошибке отправки, работе с подключенной базой или контроле ПД соберите JSON сразу после сбоя, до изменения настроек и повторных попыток. Для центральной ИИконы и УТ нужны два отдельных файла. Для чисто визуального замечания хватит номера шага, снимка окна, размера окна и масштаба, исходную диагностику можно приложить один раз.

К каждой ошибке добавьте номер шага, какой результат ожидался и что получилось, точное время, имя тестовой беседы и полный текст ошибки. Если есть код обращения, приложите его тоже. В JSON нет вопросов, ответов и файлов, поэтому для проблемы с содержимым ответа нужен отдельный пример или снимок. Ключи, пароли и заголовки Authorization присылать не нужно. Для сбоя после перепубликации IIS дополнительно нужны настройки аутентификации до и после и HTTP-подстатус из журнала IIS.
