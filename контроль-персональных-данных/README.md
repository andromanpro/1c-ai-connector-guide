# Контроль персональных данных

С версии 1.5.0 ИИкона проверяет текст перед отправкой во внешние сервисы и заменяет найденные
персональные данные подстановками. Модель видит «Ковалев Артем Андреевич, ИНН 0012345679»
вместо настоящего клиента, а человек в форме получает ответ с исходными значениями.

## Как это устроено

```
Промпт, история, вложения ─▶ поиск ПД ─▶ замена подстановками ─▶ контроль тела ─▶ провайдер
                               │                   │                              │
                               └── журнал контроля (типы и счётчики, без значений) │
                                                                                   ▼
Ответ для человека ◀── возврат исходных значений ◀─────────── ответ модели с подстановками
```

Проверка стоит на выходе из базы, а не в подсистемах: через неё идут все запросы к моделям
(чат, агентская петля, генерация изображений, эмбеддинги базы знаний), уведомления Telegram
и код диаграмм для Kroki. Новая подсистема, которая зовёт коннектор, получает контроль
автоматически.

## Что ищется

| Тип | Примеры | Как распознаётся |
|---|---|---|
| ФИО | «Иванов Иван Иванович», «Иван Иванович Иванов», «Иванов И.И.», «И.И. Иванов», «ИВАНОВ И.И.» | по отчеству или инициалам; «Имя Отчество Фамилия» — при типичном окончании фамилии (-ов, -ин, -ский, -енко…) |
| ИНН | 7707083893, 500100732259, «ИНН/КПП 7707083893/770701001» | контрольные цифры; с неверной суммой — только рядом со словом «ИНН» |
| СНИЛС | 112-233-445 95 | контрольная сумма; с неверной — рядом со словом «СНИЛС» |
| Номер карты | 4026 8434 8316 8683 | алгоритм Луна |
| Паспорт | 45 06 123456 | десять цифр рядом со словом «паспорт» |
| Телефон | +7 903 123-45-67, 8 (903) 123 45 67 | российский номер из 11 цифр |
| Электронная почта | petrov@mail.ru | по структуре адреса |

Не находятся: одиночные фамилии, наименования организаций, адреса, даты рождения.

## Чем заменяется

Подстановки берутся из заведомо несуществующих диапазонов и проходят те же проверки, что и
оригинал, — модель не спотыкается о «битые» номера:

| Тип | Подстановка |
|---|---|
| ФИО | ФИО того же рода и в той же форме из списков распространённых имён |
| ИНН | регион 00, верные контрольные цифры |
| СНИЛС | 000-…, верная контрольная сумма |
| Карта | BIN 0000, верная сумма Луна |
| Телефон | +7 000 … |
| Почта | user.…@example.com |
| Паспорт | серия 00 00 |

Одно значение в пределах запроса получает одну подстановку, поэтому модель понимает, что
речь об одном человеке. В следующем запросе подстановки другие: по ним нельзя связать
обращения к провайдеру между собой.

## Каналы и режимы

| Канал | Что проверяется | По умолчанию |
|---|---|---|
| Запросы к моделям | системный и пользовательский промпт, история, имена файлов вложений, сообщения и аргументы вызовов агентской петли, результаты инструментов, промпт генерации изображений, текст для эмбеддинга | Маскировать |
| Уведомления Telegram | текст, подпись, имя файла | Маскировать |
| Рендер диаграмм (Kroki) | код диаграммы | Логировать |

| Режим | Что происходит |
|---|---|
| **Выключен** | текст уходит как есть, в журнал ничего не пишется |
| **Логировать** | текст уходит как есть, находки записываются в журнал |
| **Маскировать** | найденное заменяется подстановками, событие пишется в журнал |
| **Блокировать** | запрос с находками или с вложением не отправляется |

Для Telegram при отказе вместо уведомления уходит короткая заглушка без данных — оператор
видит, что событие было. Файл при отказе не отправляется. Если проверка сама упала, в режимах
«Маскировать» и «Блокировать» запрос останавливается, а не уходит без проверки.

## Настройка

Обработка **«Контроль персональных данных»** (подсистема «Коннектор ИИ»):

- режимы трёх каналов; флажок «Сервер Kroki свой» выключает проверку кода диаграмм,
  если Kroki стоит в вашем контуре;
- какие типы искать — хотя бы один должен остаться включённым;
- срок хранения событий журнала (по умолчанию 30 дней, чистит регламентное задание);
- **проверка текста**: вставьте любой текст и нажмите «Проверить текст» — форма покажет, что
  найдено, чем заменится и как текст уйдёт в режиме «Маскировать». Ничего не отправляется
  и в журнал не пишется;
- кнопка **«Журнал контроля»** открывает события: канал, модель, решение, типы находок,
  количество замен.

## Режим модели и доверенный маршрут

В карточке модели (справочник «Модели ИИ») на вкладке **«Персональные данные»**:

- **Режим контроля** — переопределяет режим канала для этой модели. Например, облачной
  модели — «Блокировать», остальным — «Маскировать».
- **Маршрут доверенный** — для своего сервера модели (Ollama, LM Studio, шлюз в контуре):
  запросы к ней уходят без проверки. При записи карточки фиксируется отпечаток маршрута —
  адрес, прокси и имя модели. Если потом изменить любое из них, доверие снимается
  автоматически, и запросы снова проверяются. Состояние видно на той же вкладке; чтобы
  доверить новый маршрут, снимите флажок, запишите карточку и установите его снова.

## Ответ для человека

В обработке «Тест ИИ» и генераторе диаграмм ответ модели показывается с исходными
значениями. Под ответом появляется отметка «🔒 Персональные данные заменены при отправке».
Если модель просклоняла подставную фамилию («Ковалеву»), такое место восстановить нельзя —
отметка сменится на предупреждение, а в тексте останется подстановка.

Машинный результат, кеш ответов, журнал запросов ИИ и мониторинг ошибок остаются
с подстановками. Кеш для запросов с заменами не используется.

В своём коде ответ восстанавливается так:

```bsl
Контекст = КИИ_КонтрольПерсональныхДанных.НовыйКонтекст();
Результат = КИИ_КоннекторИИ.ЗапросКМодели(Модель, Промпт, Контекст);
ДляЧеловека = КИИ_КонтрольПерсональныхДанных.ВосстановитьДляЧеловека(Результат.ТекстОтвета, Контекст);
// ДляЧеловека.Текст - ответ с исходными значениями,
// ДляЧеловека.Статус - БезПодстановок, ВосстановленоПолностью, ЧастичноНеУзнано
```

## Ограничения

- Содержимое вложений (картинки, PDF) не читается: в «Блокировать» запрос с вложением не
  уходит, в «Маскировать» уходит как есть.
- MCP-сервер не охвачен: внешний агент получает данные по правам своей роли — см.
  **[MCP-сервер](../mcp-сервер/README.md)**.
- Поиск по базе знаний через внешний эмбеддер не находит фрагмент по конкретному ФИО или
  номеру: у вопроса и фрагмента разные подстановки. Для такого поиска — локальный эмбеддер
  с доверенным маршрутом.
- Слово с заглавной перед именем и отчеством («Звонил Иван Иванович») может попасть в замену.
- Подставные ФИО берутся из списков: если в той же операции позже встретится реальный
  человек с точно таким же ФИО, его имя уйдёт без замены.
- Это техническая замена значений, а не юридическое обезличивание.

## Условные обозначения

**ПД** — персональные данные. **Подстановка** — значение, которое уходит вместо исходного.
