# Эксперты ИИ

Эксперт — это модель плюс системный промпт: кем модели быть и как отвечать. Один и тот же
ключ и одна модель могут стоять за несколькими экспертами: «Консультант по 1С», «Генератор
диаграмм», «Юрист по договорам» отличаются только промптом и базой знаний.

Справочник: «ИИкона» → «Эксперты ИИ».

![Карточка эксперта: модель, промпт и категории знаний](images/kartochka.png)

*Исторический снимок до 1.6.2; расположение элементов и подписи в текущей версии изменены.*


## Сообщения об ошибках инструментов: 1.8.5

Чат отдельно показывает отказ выбранной базы и ошибку формата DSML,
даже если модель не смогла их пояснить. Команды из текстовой разметки
не исполняются. Подробности и порядок проверки приведены в
[описании агентской петли](../агентская-петля/README.md#ошибки-формата-и-источников-185).


## Поля карточки

| Поле | Что задает |
|---|---|
| Наименование | как эксперт называется в списках выбора |
| Модель | элемент «Модели ИИ», которому уйдет запрос: адрес, ключ, формат API |
| Описание эксперта (промпт) | системный промпт — роль, тон, формат ответа, ограничения |
| Категории знаний (RAG) | из каких категорий базы знаний эксперт берет справку; пусто — отвечает без базы знаний |

Таблица «Категории знаний (RAG)» появилась в карточке в 1.6.1. В более ранних версиях
табличная часть у эксперта была, но заполнить ее можно было только программно.

## Кто работает через эксперта

| Где | Что берет от эксперта |
|---|---|
| «Чат с экспертом» | модель, промпт и категории знаний |
| Генератор диаграмм, режим «по описанию» | модель и промпт; база знаний не подмешивается |

Мониторинг ошибок и аудитор кода эксперта не используют: модель задается в их собственных
настройках (см. [анализ ошибок](../анализ-ошибок/README.md)).

Обе формы запоминают последнего выбранного эксперта и подставляют его при следующем открытии.

## Инструменты в чате

С версии 1.7.3 в «Чате с экспертом» рядом с выбором эксперта есть флажок
«Использовать инструменты». При первом открытии он выключен; значение запоминается
в настройках формы.

1. В карточке модели эксперта включите «Поддерживает инструменты (function-calling)»,
   если модель и её API поддерживают вызовы функций.
2. Откройте «Чат с экспертом», выберите эксперта и включите «Использовать инструменты».
3. Задайте вопрос, требующий сведений из базы, например: «Какие регистры сведений
   есть в этой конфигурации?»

Эксперту доступны сведения о конфигурации, дерево метаданных, структура объекта и
запросы к данным на чтение. Запрос выполняется с правами пользователя.
Модель сама выбирает, нужен ли инструмент для ответа. ИИкона выполняет вызов и
возвращает результат модели; для окончательного ответа может потребоваться несколько
обращений к API. После ответа показаны суммарные токены, время и число вызовов инструментов.

Системный промпт, база знаний эксперта, выбранная история диалога и вложения сохраняются.
Текст проходит контроль персональных данных во всех раундах. Для человека подстановки
в окончательном ответе восстанавливаются по обычным правилам чата.

Переключатель включает встроенные инструменты; источники задаются в настройках диалога. Для чтения метаданных текущей базы
не требуется shim или HTTP-публикация MCP-сервера. Подключение инструментов произвольного внешнего MCP-сервера остаётся в плане развития. С версии 1.8.0 доступны [списки инструментов по моделям](../настройка-моделей/README.md#инструменты-модели) и [выбор подключённых баз](../подключения-баз/README.md).

Если у модели выключен признак поддержки инструментов, чат вернёт понятную ошибку.
Обычный запрос выполняется при выключенном флажке.
Список инструментов и действующие ограничители описаны на странице
[агентская петля](../агентская-петля/README.md).

## Настройки и просмотр контекста

Новые переключатели истории, знаний и вложений, вкладки «Перед отправкой» и «Журнал диалога» описаны на странице [«Контекст и журнал чата»](../контекст-чата/README.md). В публичной 1.7.4 их ещё нет.

## Контекст запроса в журнале

С версии 1.7.4 на вкладке «Вопрос и контекст» записи журнала инструментального
запроса видны вопрос, системные инструкции и JSON с `messages` и `tools`.
Сообщения и результаты инструментов сохраняются после контроля персональных данных.
Отдельные раунды связаны полем «Корреляция агента»; контекст остаётся и у раунда,
завершившегося ошибкой модели.

Обычный запрос без инструментов сохраняет прежний массив истории. В журнал не
добавляются HTTP-заголовки и ключ авторизации модели. Подробнее —
[что остаётся в базе](../агентская-петля/README.md#что-остается-в-базе).

## Реальные примеры из чата

Примеры сняты 16.10.2026 в ИИконе 1.7.3 на демонстрационной конфигурации БСП 3.1.
Эксперт использует модель `deepseek/deepseek-v4-pro` через OpenRouter.
В обоих случаях включён флажок `Использовать инструменты`.

### Структура конфигурации

Вопрос: каким реквизитом связаны `_ДемоНоменклатура` и `_ДемоВидыНоменклатуры`,
какого типа реквизиты `Цена` и `СтранаПроисхождения`?

Модель проверила структуру объектов и указала ссылочный реквизит `ВидНоменклатуры`.
Тип цены: `Число`; тип страны: `Справочник.СтраныМира`.
В показанном ответе: 2 вызова инструментов, 4011 токенов, 11 секунд.

![Петля в чате: проверка структуры объектов](images/chat-tools-metadata-1.7.3.png)

### Данные базы

Вопрос: сколько непомеченных элементов содержат номенклатура, её виды и страны мира?
Модель получила фактические количества и сделала вывод об отсутствии товарных позиций.
Числа совпали с независимым чтением базы перед запуском чата:

| Справочник | Количество |
|---|---:|
| `_ДемоНоменклатура` | 0 |
| `_ДемоВидыНоменклатуры` | 2 |
| `СтраныМира` | 1 |

В показанном ответе: 3 вызова инструментов, 3568 токенов, 7 секунд.
Числа относятся к состоянию этого демонстрационного стенда. На другой базе они будут отличаться.
Причины отсутствия записей по этим количествам определить нельзя.

![Петля в чате: запрос фактических данных](images/chat-tools-data-1.7.3.png)

Это снимки настоящего клиента 1С после запросов к модели. При съёмке исключена левая
панель разделов, текст вопроса и ответа сохранён. Время и расход токенов зависят от модели
и конкретного обращения.

## Как писать промпт

Промпт уходит модели системным сообщением перед каждым вопросом. Что в нем работает:

- **Роль и аудитория.** «Ты консультант по 1С:Предприятие 8.3, отвечаешь программисту».
- **Формат ответа.** «Отвечай кратко, код — на встроенном языке 1С». «Чат с экспертом» показывает
  Markdown, так что заголовки, списки и блоки кода выводятся оформленными.
- **Границы.** «Если в справке нет ответа, так и скажи» — полезно для эксперта с базой знаний.

Промпт проходит [контроль персональных данных](../контроль-персональных-данных/README.md)
вместе с вопросом: ФИО или ИНН, записанные прямо в промпт, уйдут модели подстановками.

## База знаний в ответах

Если у эксперта заполнены категории знаний, «Чат с экспертом» перед отправкой вопроса:

1. Ищет в базе знаний этих категорий три фрагмента, ближайших к тексту вопроса по смыслу
   (как устроен поиск — на странице [RAG](../rag/README.md)).
2. Отбрасывает фрагменты, которые этой модели показывать нельзя: фрагменты с политикой
   «Только РФ» попадут только к модели с классом egress «Только РФ». Фрагменты с политикой
   «Запрещено внешнее» не индексируются и в поиск не попадают вовсе.
3. Добавляет найденное к промпту эксперта блоками `[СПРАВКА N НАЧАЛО]` … `[СПРАВКА N КОНЕЦ]`
   с оговоркой, что это справочный материал, а не инструкции. Промпт вместе со справкой
   ограничен 8000 символами: фрагменты, которые не влезли, отбрасываются. Если промпт
   эксперта сам занимает почти весь лимит, справка не добавляется вовсе — держите промпт
   коротким.

Ищется только текущий вопрос, без истории диалога. Если поиск не сработал — нет
эмбеддера, индекс пуст, эмбеддер вернул ошибку — эксперт отвечает без справки, а вопрос
все равно уходит модели.

Порядок настройки:

1. Модель-эмбеддер, категории и документы базы знаний, индексация — по шагам со страницы
   [RAG](../rag/README.md#настройка-по-шагам).
2. В карточке эксперта в таблице «Категории знаний (RAG)» нажмите «Добавить» и выберите
   категорию. Категорий может быть несколько. Запишите карточку.
3. Задайте вопрос этому эксперту в «Чате с экспертом».

## Эксперт для генератора диаграмм

Если в генераторе диаграмм эксперт не выбран, рядом с полем видна кнопка «Создать эксперта».
Она создает эксперта «Генератор диаграмм» с готовым промптом из макета обработки. Модель в
новом эксперте пустая: откройте его и выберите модель — запрос уходит модели эксперта. Подробнее — в
[диаграммах](../диаграммы/README.md).

## Если эксперт отвечает не так

| Что видно | Что проверить |
|---|---|
| «Не заполнен Эксперт ИИ» | в «Чате с экспертом» не выбран эксперт |
| Ответ не опирается на базу знаний | заполнена ли таблица «Категории знаний (RAG)»; проиндексированы ли документы и получены ли эмбеддинги; политика категории против класса egress модели |
| Модель отказывается принять картинку | формат API или сама модель не принимает файлы — см. [вложения](../вложения/README.md#какие-модели-принимают-файлы) |
| Ошибка модели (401, 404, таймаут) | карточку модели — см. [начало работы](../начало-работы/README.md#если-модель-не-отвечает) |
